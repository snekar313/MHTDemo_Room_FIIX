Deliver manifest, immutable originals, photo index, source extracts and conflict register. Accept when hashes match and all missing sources are visible. Current gap: two TXT guide copies remain missing.

## Stage 1: fresh asset-only release (current)

Deliver 46-row Assets.csv, matching review workbook, canonical hierarchy/schema, A26 parent evidence and offline validation results. No task groups, work orders or existing-record updates. ## Stage 2: IAB/PST BOM

Deliver refined BOM with exact-vs-candidate catalog fields, quantities, ratings, firmware, I/O/channel counts, power/protection calculations, drive/motor/cable pairings, network ports and third-party materials. Retain the source builder's IAB Entry Action per line. An engineer uses IAB/PST to create, validate and save native artifacts; record application/version and reopen evidence. No native file is claimed in this repository today.

## Stage 3: maintenance groups and tasks

The source contains 8 groups and 16 tasks. Deliver approved task definitions, expected results, applicability, owner/interval approval, class-to-asset mapping, and tenant-specific imports after actual import templates are supplied. Existing TaskGroups.csv is a summary with counts only. Its six existing groups are not replaced or copied into new IAB groups. Proposed source frequencies are not approved schedules. Safety tasks are planning records pending qualified procedure review.

## Stage 4: work orders / commissioning

Deliver reviewed commissioning plans and tenant-formatted drafts only after scope is reactivated. Verify generated-code behavior, exact asset reference syntax, tenant statuses/types/priorities and assignments. Do not copy work-order codes, user assignments, completion state or actual hours from tenant examples. Draft plans are not executed work or approved schedules.

## Stage 5: topology and as-built evidence

Deliver proposed logical network and asset hierarchy diagrams now. Later add a device/interface IP register, port-to-port physical topology, cable IDs, VLAN/routing/NAT and safety/motion architecture with exact configuration sources. Keep proposed and as-built views separate. Do not infer missing switch/router capacity or safe architecture from a diagram.

## Stage 6: tenant validation and Cloud handoff

After authorized test import, preserve results and a post-import export with counts, parents and new tenant IDs. Publish reviewed repository changes and verify an actual Cloud validation run. Keep Cloud execution, GitHub publication, IAB/PST validation and tenant import status separate.
